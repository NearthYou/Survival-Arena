# 첫 DX11 프레임을 자동 테스트까지 연결하기

## 상황

저장소에는 CMake와 테스트 하네스만 있었고 GPU에 명령을 보내는 코드는 없었다. 이번 변경의 목표는 화려한 화면이 아니라 Win32 진입점부터 draw와 present까지 끊기지 않는 최소 경로를 만드는 것이었다.

구현 범위는 일부러 좁혔다. 숨김 창에서도 실행할 수 있고, 하드웨어 GPU가 없는 CI를 고려해 WARP를 선택할 수 있으며, 지정한 프레임 수가 지나면 스스로 종료해야 했다.

## 재현

RED 상태에서는 다음 명령이 `DX11 renderer is not implemented`를 출력하고 종료 코드 2를 반환했다.

```powershell
./scripts/build.ps1
./scripts/test.ps1
```

스모크 실행 인자는 다음과 같다.

```text
dxa_client --warp --hidden --no-vsync --frames 3 --width 320 --height 180
```

## 관찰

첫 시도에서는 CTest가 14개 테스트를 모두 통과했다고 표시했다. 하지만 추가한 스모크 테스트가 목록에 없었다. 실행 파일이 정상이라는 뜻이 아니라 테스트 자체가 등록되지 않은 상태였다.

원인은 루트 `CMakeLists.txt`에서 `apps/client`를 추가한 다음 `enable_testing()`을 호출한 순서였다. `enable_testing()`을 하위 디렉터리보다 앞으로 옮기고, Visual Studio 다중 구성에 맞게 `ctest --build-config Debug`를 전달하자 15번째 테스트가 실제로 실행됐다. 그때 미구현 종료 코드로 예상한 RED가 확인됐다.

## 가설과 대안

처음 렌더 경로는 하드웨어 장치만 지원할 수도 있었다. 이 방법은 코드가 조금 짧지만 자동 검증이 GPU와 데스크톱 세션에 묶인다. 반대로 렌더 결과까지 이미지 비교하는 테스트는 첫 변경에서 필요한 범위를 넘는다.

그래서 하드웨어와 WARP를 같은 코드에서 선택하고, 숨김 창으로 3프레임을 끝까지 처리하는 것을 이번 경계로 정했다. 이미지 캡처는 렌더 결과를 비교할 기준 장면이 생긴 뒤 추가한다.

## 구현

Win32 창은 키 입력을 `InputState`로 전달하고 메시지 큐를 비우는 역할만 맡는다. `GraphicsDevice`는 swap chain, back buffer view, depth buffer와 viewport를 소유한다. `ForwardRenderer`는 HLSL을 실행 시점에 컴파일하고 큐브용 정점·인덱스·상수 버퍼를 만든다.

매 프레임에는 고정 카메라의 view/projection과 시간 기반 world 회전을 합쳐 상수 버퍼에 기록한다. 이 단계에서는 재질, 조명, 에셋 로더를 넣지 않았다.

## 검증

```text
Windows Debug 빌드: 성공
GoogleTest와 CTest: 15/15 통과
WARP 숨김 창 3프레임: 0.19초, 종료 코드 0
RTX 하드웨어 960x540 120프레임: 종료 코드 0
```

자동 테스트가 확인한 것은 장치 생성, 셰이더 컴파일, 버퍼 생성, draw, present, 정상 종료다. 화면에 그려진 픽셀의 정확성은 아직 확인하지 않았다.

## 남은 한계

- 창 크기 변경과 device lost 복구가 없다.
- debug layer 메시지를 테스트 실패로 승격하지 않는다.
- 화면 캡처와 픽셀 비교가 없다.
- 큐브 데이터가 렌더러 안에 있어 메시와 재질을 재사용할 수 없다.
- 현재 셰이더는 정점 색상만 출력하며 조명 계산이 없다.

다음 변경에서는 메시와 머티리얼의 소유 경계를 먼저 분리한 뒤, 같은 스모크 장면을 포워드 렌더링 기준선으로 확장한다.
