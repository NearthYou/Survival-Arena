# 기준선 제외 기록

이 디렉터리는 첫 1920×1080 Release 실행 원본이다. 렌더링은 720프레임을 끝까지 완주했지만 GPU timestamp가 600개 중 302개 비어 있어 포워드 기준선으로 채택하지 않았다. `frames.csv`와 `summary.json`은 수정하지 않았다.

## 재현 조건

- commit: `361631386a5c33e3be90bb54fcb9adb8a216035c`
- adapter: NVIDIA GeForce RTX 3050 Ti Laptop GPU
- 장면: 캐릭터 24명, AI 100개, 정적 객체 1,000개, 동적 광원 32개
- 준비 120프레임, 측정 600프레임, seed `20260823`
- 실행: `scripts/run_benchmark.ps1` 기본 인자

## 확인 과정

처음 16개 측정 프레임은 GPU 값이 있었고 이후에는 빈 구간과 16개 안팎의 유효 구간이 반복됐다. 빈 값은 query 시작 실패, disjoint, 종료 시 미해석을 같은 형태로 저장하고 있었기 때문에 패턴만으로 원인을 정하지 않았다.

같은 Release 실행에 진단 집계를 임시로 추가하고 1920×1080 120프레임을 다시 측정했다.

```text
고정 16슬롯: 시작 거부 17, 정상 해석 103, disjoint 0, 미해석 0
프레임 수 슬롯: 시작 거부 0, 정상 해석 120, disjoint 0, 미해석 0
```

원인은 프레임마다 기다리지 않도록 만든 비동기 query 풀이 16개로 고정돼 있었고, 실제 드라이버의 결과 회수 지연이 그보다 길었던 것이다.

## 선택

프레임마다 `GetData`를 기다리면 CPU 프레임 시간에 대기 비용이 섞이므로 사용하지 않았다. 누락 프레임을 제외하고 통계를 내는 방식도 결과를 좋게 보이게 만들 수 있어 채택하지 않았다. 측정 프레임 수만큼 query 슬롯을 실행 전에 만들고, 종료 시까지 결과가 없는 값만 누락으로 남기도록 수정했다.

회귀 테스트는 해석하지 않은 query 20개를 연속 제출해 구성한 슬롯이 모두 사용 가능한지 확인한다. 수정 commit은 `69b7a53`이다.
