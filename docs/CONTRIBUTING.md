# 작업 규칙

## 브랜치

`feat/`, `fix/`, `docs/`, `test/`, `chore/` 접두사를 사용한다. 브랜치 이름에 자동화 도구 이름을 넣지 않는다.

## 커밋

제목은 `type(scope): 한국어 명사형 요약` 형식을 사용한다. 본문에는 다음 세 항목을 남긴다.

```text
이유: 변경이 필요한 배경
핵심 변경: 동작과 경계
검증: 실제로 실행한 명령과 결과
```

한 커밋은 독립적으로 검토할 수 있는 한 가지 변경만 포함한다. 커밋 수를 늘리기 위한 분할과 날짜 조작은 하지 않는다.

## 문제 해결 기록

개발 기록은 증상, 재현 조건, 가설, 비교 대안, 구현, 결과, 남은 한계 순으로 작성한다. 의도적으로 단순하게 만든 기준 구현을 예상하지 못한 장애처럼 표현하지 않는다.
