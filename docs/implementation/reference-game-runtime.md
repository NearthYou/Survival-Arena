# 원본 게임 실행

이 실행 경로는 레퍼런스 저장소의 Client와 Engine 전체를 외부 의존성으로 빌드한다. 원본의 입력 처리, 상태 머신, UI, 렌더 순서와 FMOD 사운드를 사용한다. 기존 dxa_client의 별도 gameplay 구현을 실행하는 경로가 아니다.

재현 기준은 [원본 시연 영상](https://www.youtube.com/watch?v=b6XVkd0xc-E)과 같은 시점의 [DirectX11-Engine-Client](https://github.com/HyangRim/DirectX11-Engine-Client) 커밋 `01b820a3ebcfd473a898dec1f5bc67c4ac77261e`다. 이후 HEAD에는 시작 화면 생략, 몬스터 배치 축소와 늑대 행동 트리 변경이 있어 구분한다. 원본의 코드와 자산을 직접 작성한 결과로 소개하지 않는다.

## 구성과 빌드

Visual Studio 2022 Community C++ 도구와 PowerShell 7이 필요하며 CMake 3.25 이상을 PATH에서 실행할 수 있어야 한다. SOURCE_ROOT는 원본 저장소, RUNTIME_ROOT는 이 저장소와 원본 저장소 밖의 로컬 빌드 폴더다.

```powershell
./scripts/bootstrap.ps1
cmake --preset windows-msvc-debug `
  -DDXA_REFERENCE_SOURCE_ROOT=SOURCE_ROOT `
  -DDXA_REFERENCE_RUNTIME_ROOT=RUNTIME_ROOT
cmake --build --preset windows-msvc-debug --target dxa_reference_game
cmake --build --preset windows-msvc-debug --target play_reference_game
```

`dxa_reference_game`은 게임을 빌드하고 무결성을 검사한다. `play_reference_game`은 검사를 거쳐 시작 화면을 연다. 구성된 실제 출력 경로는 CMake의 `DXA_REFERENCE_GAME_DIRECTORY`에 기록된다.

같은 출력이 이미 있으면 무결성을 다시 검사해 재사용한다. CMake clean 이후나 새 빌드 디렉터리에서도 완성된 외부 게임을 덮어쓰지 않는다. 미완성 출력이나 검증에 실패한 출력은 자동 삭제하지 않는다.

빌더, 패치 또는 실행판 준비 정책이 바뀌면 다른 출력 경로를 사용한다. 적용할 수정 목록이 달라졌는데 이전 실행판을 재사용하는 일이 없도록 준비 스크립트도 빌드 식별값에 포함한다.

두 경로를 지정하지 않으면 기존 공개 빌드에는 이 타깃이 추가되지 않는다. 서버, 네트워크와 벤치마크 타깃은 독립적으로 유지된다.

## 원본 경로만 검증하기

원본 전용 검증은 `cmake/ReferenceGameTests.cmake`에 분리되어 있다. 위의 원본 빌드를 끝낸 뒤 다음 명령으로 실행한다. 실험용 gameplay의 미커밋 변경 없이도 등록되고 실행되어야 한다.

```powershell
ctest --test-dir out/build/windows-msvc-vs-debug -C Debug `
  -R "^Reference(Oracle|Game)" --output-on-failure
```

원본 출력이 구성된 환경에서는 13개 검증을 실행한다. 출력이 구성되지 않은 환경에서는 원본 스냅샷이 필요한 8개를 제외하고 빌더, 실행기, CMake와 프레임 캡처 관련 검증을 등록한다. 이것은 사용자 플레이와 시각 승인을 대신하지 않는다.

## 충돌 디버그 표시

충돌 구와 박스는 기본으로 숨긴다. 게임 중 F3을 누르면 표시가 켜지고, 다시 누르면 꺼진다. 충돌 판정, 공격 범위와 피해 계산은 바꾸지 않는다. 스킬 자체의 범위 이미지나 이펙트도 숨기지 않는다.

이 옵션은 사용자 요청에 따른 원본 대비 변경이다. 외부 복사본의 `LumiaIsland::LateUpdate`에 표시 제어만 추가하고 `collision-debug-toggle-v1`로 기록한다. 원본 checkout과 추출한 원본 스냅샷은 그대로 보존한다.

## 캐릭터 선택 유지

선택 화면의 번호는 확인 버튼을 반복해서 눌러도 바뀌지 않는다. 실제 게임 씬으로 넘길 때만 니키와 비앙카의 런타임 번호로 변환한다. 시작 처리마다 선택 번호를 다시 빼서 니키가 비앙카로 바뀌던 문제를 `character-selection-index-v1`로 수정했다. 같은 선택값을 제한시간 종료에도 사용한다.

스킨 버튼은 미리보기만 바꾼다. `skin-selection-isolation-v1`은 스킨 클릭에 연결돼 있던 시작 호출을 제거한다. 스킨 번호로 캐릭터 선택이 덮어써지거나, 시작 버튼을 누르지 않았는데 대기시간이 줄어들지 않는다. 시작 버튼의 빠른 시작 처리와 원본의 55초 제한시간은 그대로 유지한다.

별도 계측 실행판에서 실제로 생성된 캐릭터 버튼과 비앙카 5개, 니키 6개 스킨 버튼을 반복 호출한다. 시작을 누르기 전 12초 동안 원래 대기시간이 유지되는지, 시작 버튼을 반복해서 누르고 스킨을 다시 바꿔도 선택한 캐릭터가 실제 맵에 등장하는지 확인한다. 데스크톱 입력은 사용하지 않는다.

## 처음부터 대상을 선택할 수 있도록 수정

카메라 행렬을 갱신한 뒤 화면 기준 공간 인덱스를 만든다. 기존에는 이동한 카메라 위치와 이전 행렬이 섞여 저장되어, 시작 지점에서 움직이지 않으면 늑대를 가리켜도 대상이 검색되지 않을 수 있었다. `picking-camera-sync-v1`은 인덱스 생성 전 행렬만 동기화하며, 카메라 배치와 충돌 판정은 유지한다.

## 연속 동작의 애니메이션 유지

반격의 전투 상태가 끝난 뒤 E를 쓰면 피해는 들어가도, 남아 있던 반격 애니메이션이 E 요청을 버릴 수 있었다. `player-animation-sync-v1`은 전투 상태가 허용한 플레이어 동작을 애니메이션 상태에도 반영하고, 먼저 도착해 거절된 요청을 다시 맞춘다. 새 동작이 없을 때는 기존 끝동작을 유지하며, 같은 요청을 반복해도 클립을 처음부터 다시 재생하지 않는다. 몬스터 애니메이션 전환은 바꾸지 않는다.

`player-animation-episode-sync-v1`은 한 번 반영한 동작을 완료 대기 중에 다시 시작하지 않도록 한다. 애니메이션 종료보다 전투 상태의 종료 처리가 늦으면, 앞선 동기화가 끝난 Q를 다시 요청할 수 있었다. 마지막으로 반영한 동작과 아직 반영을 기다리는 요청을 구분해 이를 막는다. 새 스킬 사용, 늦게 허용된 동작과 추격 중 달리기는 계속 동기화한다. 스킬 수치와 원본 애니메이션 시간은 바꾸지 않는다.

공격 상태에는 적에게 접근하는 이동도 포함된다. `combat-approach-animation-v1`은 공격 상태에서 NavMeshAgent가 이동 중이면 달리기 모션을 유지하고, 멈추면 공격 모션으로 전환한다. 스킬 상태는 이 이동 판정으로 덮어쓰지 않는다. 앞선 동기화 수정과 함께 적용하며, 이전 실행판의 검증을 위해 기존 패치도 그대로 지원한다.

## 제작 준비값 전달

`craft-state-preparation-v1`은 제작에 사용할 상태에 레시피 번호와 등급별 시간을 설정한다. 전환을 기다리는 동안 현재 대기나 이동 상태에 값을 써서, 정작 제작 애니메이션에는 초기화되지 않은 시간이 들어가던 문제를 수정했다. 등급별 시간 계산과 입력 순서는 유지한다. Z키는 제작을 시작하며, 목록 버튼은 원본대로 미리보기를 갱신한다.

검증용 재료로 두 번 연속 제작하고, 각 제작 뒤 대기 복귀와 장착 교체를 확인한다. 교체된 기존 장비가 인벤토리로 돌아오는지도 검사한다. 이 검증을 실제 사체에서 재료를 획득한 증거로 사용하지 않는다.

## 벽 모서리에서 멈추는 이동 수정

원본의 경로 단축 검사는 일정 간격의 점과 넓은 허용 오차를 사용해 벽 모서리의 빈 공간을 지나가는 직선을 허용할 수 있었다. 이동 보정은 그 지점을 통과시키지 않아 캐릭터가 제자리에서 달리게 됐다.

`walkable-path-smoothing-v1`은 이동 선분 전체가 NavMesh의 삼각형 안에 이어져 있는지 검사한다. 필요한 모서리 경유점을 유지하고, 짧은 거리라도 빈틈을 가로지르는 경로는 단축하지 않는다. 이동 속도, 피해, 몬스터 배치와 원본 NavMesh 자산은 바꾸지 않는다.

## 음량 설정 유지

`audio-category-settings-v1`은 배경음과 효과음을 각각 FMOD 그룹으로 관리한다. 슬라이더 설정이 현재 소리뿐 아니라 이후 재생되는 소리와 겹쳐 재생되는 소리에도 적용된다. 100%에서는 원본의 개별 소리 크기를 유지하고, 전체 정지는 두 그룹의 모든 소리를 멈춘다. 씬을 바꿔도 그룹의 음량 설정은 유지한다.

원본 설정 패널의 슬라이더와 호버 재생, 캐릭터 선택을 거쳐 게임으로 들어가는 흐름은 별도 오프라인 믹서 계측으로 검사한다. 실제 FMOD가 만든 PCM을 측정하되 데스크톱 오디오 장치는 사용하지 않는다. 이 결과를 사용자 스피커에서 직접 소리를 확인한 것으로 표시하지 않는다.

## 데이터와 검증 경계

- 선택한 커밋의 Client, Engine, Shaders와 Libraries를 새 외부 디렉터리에 추출한다. 원본 checkout은 변경하지 않는다.
- Resources는 같은 커밋과 차이가 없는지 확인한 뒤 읽기 전용 작업 원칙으로 공유한다. 코드, 바이너리와 원본 자산은 이 저장소에 추가하지 않는다.
- 실행 전 소스, 셰이더, 실행 파일과 DLL의 빌드 당시 해시를 확인한다. 다른 커밋이나 계측용 실행 파일은 플레이 경로에서 거부한다.
- 수정이 적용된 여덟 파일은 원본 스냅샷에 같은 패치를 재적용한 예상 해시와 비교한다. 열 가지 수정 중 충돌 표시와 제작 준비는 LumiaIsland에, 캐릭터 번호와 스킨 클릭은 선택 화면에, 동작 동기화와 추격 모션은 AnimationStateMachine 구현과 헤더에, 음량 설정은 SoundManager 구현과 헤더에 적용된다. 그 외 소스 차이는 허용하지 않는다. 수정된 실행 파일을 무수정 원본이라고 표시하지 않는다.
- 원본 UI 핸들러를 호출하고 프레임과 전투 상태를 수집하는 계측 빌드는 별도다. 이를 무수정 플레이 실행 파일로 표시하지 않는다.
- 계측 프로세스는 창을 숨기고 오디오 장치 출력을 비활성화해 사용자 플레이와 분리한다. 제작 계측은 원본 아이템 두 개를 테스트 재료로 넣은 뒤 원본 제작 delegate, 상태 머신, 애니메이션과 장착 핸들러를 실행한다. 이 검증은 직접 재료를 수집하는 플레이나 실제 음향 출력의 증거로 사용하지 않는다.
- 별도의 자연 획득 계측은 빈 인벤토리에서 시작한다. 원본 늑대를 실제로 처치하고, 사체를 클릭해 쇠구슬과 운동화를 얻은 뒤 Z키로 제작하고 인벤토리 버튼으로 장착한다. 클릭 좌표는 원본 카메라, 충돌체와 UI 버튼 영역에서 구하며 체력, 피해, 위치나 아이템을 주입하지 않는다. 사체에서 아이템이 제거됐는지, 인벤토리에 들어왔는지, 제작으로 재료가 소모됐는지, 장착 후 대기 상태로 돌아왔는지를 각각 확인한다.
- 스킬 계측은 프로세스 내부의 키 상태와 화면 좌표를 원본 입력 처리에 전달한다. 데스크톱 키보드나 마우스는 조작하지 않는다. 실제 처치로 포인트를 얻어 니키 Q/W/E/R와 비앙카 Q/W/E/R를 검사하며, 피해와 애니메이션, 충전과 키 해제, 방어력 복구, R의 두 피해 단계를 각각 확인한다. 체력과 포인트는 임의로 늘리지 않는다.
- 니키 Q는 짧은 충전 중 이동과 조준 방향, 쿨타임 중 재실행 여부, 5.2초 충전 후 원본의 최대 이동거리와 대기 복귀를 이어서 검사한다. 이동거리는 원본의 한 프레임 보간 초과분까지 포함하며, 검증에 맞추려고 이동 속도나 끝점을 수정하지 않는다.
- 이동과 보스 계측은 원본 NavMesh와 우클릭 입력으로 첫 지역에서 중간 사냥 지역을 거쳐 알파까지 이동한다. 두 캐릭터 모두 늑대 6마리 처치와 성장, 알파의 공격과 스킬 발동, 살아 있는 플레이어의 보스 처치를 확인한다. 니키는 공격 대상을 추격하는 동안 실제 이동과 달리기 모션이 함께 유지되는지도 검사한다. 순간이동, 체력 보충과 직접 피해 주입은 사용하지 않는다.
- 소스와 바이너리 일치 검사는 직접 플레이와 영상 비교를 대신하지 않는다. 기존 gameplay 테스트의 통과 여부도 이 원본 실행 경로의 승인 근거로 대체하지 않는다.
