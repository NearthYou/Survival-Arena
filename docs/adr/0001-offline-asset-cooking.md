# ADR 0001: 범용 에셋을 오프라인에서 엔진 포맷으로 변환

- 상태: 채택
- 날짜: 2026-08-23

## 상황

클라이언트가 FBX와 glTF를 시작할 때마다 Assimp로 읽으면 범용 포맷 파싱과 애니메이션 계층 평가가 런타임에 남는다. 서버에는 이 의존성이 필요하지 않고, 렌더 스모크도 원본 파일 구조에 따라 달라질 수 있다.

## 결정

Assimp는 Windows 에셋 도구에서만 사용한다. 모델은 버전이 붙은 little-endian `.dxam` 파일로 변환한다. 정점은 위치, 노멀, UV, 최대 4개 관절 인덱스와 정규화 가중치를 저장한다.

애니메이션은 node key를 런타임에 평가하지 않는다. 도구가 30Hz로 관절 최종 행렬을 계산해 clip별 palette로 저장하고, 클라이언트는 현재 시간 이전 sample을 선택해 최대 64개 행렬을 DX11 상수 버퍼에 올린다. 정점 변형은 vertex shader에서 처리한다.

색상 텍스처는 DirectXTex로 전체 mip chain과 BC7 sRGB DDS를 만든다. 런타임은 DirectXTK의 DDS loader만 사용한다.

## 비교한 대안

런타임 Assimp 로딩은 구현이 짧지만 시작 시간, 배포 의존성, 형식별 차이를 게임 실행 경로로 옮긴다.

glTF 전용 런타임 로더는 FBX보다 공개 규격이라는 장점이 있다. 다만 이번 범위에서는 원본 제공 형식이 서로 다르고 텍스처 가공과 팔레트 bake도 필요해 별도 cooked 경계가 더 단순했다.

TRS key를 엔진 포맷에 보존하고 런타임에서 보간하는 방법은 clip 전환과 가변 재생에 유리하다. 첫 버전은 한 캐릭터의 반복 재생만 필요하므로 파일 크기가 늘어나는 대신 실행 경로가 단순한 30Hz palette를 선택했다.

## 결과

Linux target에는 Assimp, DirectXTex, DirectXTK가 설치되지 않는다. 런타임 모델은 명시적 버전과 범위 검사를 거치며, 원본 팩이 없어도 cooked LFS 파일로 같은 장면을 실행할 수 있다.

반면 30Hz보다 부드러운 보간, animation blending, root motion은 아직 지원하지 않는다. 캐릭터 22개 clip을 모두 palette로 저장해 원본보다 cooked 파일이 작아진다는 보장도 없다. 포맷을 바꾸면 버전을 올리고 이전 버전 처리 방침을 별도로 정해야 한다.
